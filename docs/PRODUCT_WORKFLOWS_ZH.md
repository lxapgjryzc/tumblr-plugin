## 已确认的全局 reblog 定义

用户最新确认：**reblog 固定转发当时的正文和标签，创建后不再修改；原帖正文、图片或排布更新后，再转发一次，旧版保留。改标签不算新版本，不触发再次转发。** 下次因内容更新而转发时，才使用那一次创建时的标签。详细规则见 [REBLOG_POLICY.md](REBLOG_POLICY.md)，同时适用于桌面端、插件和素材博客，覆盖旧的标签同步／副本修复规则。此次是需求修订，代码适配尚待完成。

同一内容版本反复扫描或重启不能重复转发；目标已有旧版本不能阻止新版。公开／隐藏仍由独立展示规则管理，不能借状态修改改写快照。素材 AI、标签整理、模板更新也不得回写已有转发的正文或标签。

本次交接报告称桌面端 23 项测试及插件测试通过，账号只读同步读取 6 个博客、598 条帖子、使用 47 次请求。本轮仅核对本地文档和部分代码，未重跑这些测试，也未操作账号。博客用途属于本地配置，不写入公开需求稿。

- 图片随一次发布请求上传、直接创建为所选状态，替代原稿的分步上传和先建远端草稿提案；稳定排布、失败保留和结果不明时不盲目重发仍是验收要求。一次请求不能保证代码绝不会把图片对应错。
- 新关注目前仅复核，自动拉黑需先完成识别规则评估；举报需在 Tumblr 操作并由用户确认。减少日常人工清理仍是目标，没有改成永久手动模式。

- 已发布正文编辑、访客可见性检查、完整原生功能能力清单仍有缺口，不能因当前没做就从需求中删除。当前只确认远端帖子状态，不声称访客已看不到。
- 回执丢失后：2026-11-06 起按发布开始后的全部帖子查找，比对所有文字块、图片数、并排分组和标签；找不到不再自动判失败，而是保持“结果未知”并每 6 小时再找，只有用户在 Tumblr 核对后选择“确实没发出去”才允许再发。已有模拟测试，真实丢回执场景未测。
- 账号使用社区标签。2026-11-06 经用户同意，用桌面端同样的完整修改原样提交两篇已有帖子：分类器标签（私密转帖）和作者自设标签（公开原帖）都保留，桌面端标签能力已设为通过。改变可见性的修改未单独测试。“不使用社区标签”不适用于此账号。

社区标签测试用的是已有帖子而非新建测试帖，所以无需清理；测试在任务队列之外进行，没有放行积压任务。开启自动化前先在“活动”页查看待执行任务。详见状态清单。

## 已确认的产品定位

**应用程序是本体，插件是附属的浏览器助手。** 写作、发布、内容管理、分类模板、规则、AI 和任务记录由应用统一负责。浏览器完全退出后，应用仍能发布和执行核心管理任务；插件只保留需要网页环境或在网页中操作明显更方便的功能。首版重点是本地使用体验，公开博客主题另行讨论。

用户负责日常创作和少量选择：写什么、发到哪里、哪些旧帖值得一直展示。工具负责重复工作：整理标签、分发、按时间隐藏、发现需要处理的新关注，并提供能看懂的执行结果。

### 已确认的应用与插件分工（2026-11-06）

| 功能 | 应用程序 | 插件 |
|---|---|---|
| 写作与发布 | 完整编辑器、草稿、预览、发布和恢复 | 在 Tumblr 已打开的输入框里提供标签建议／模板插入，不另做编辑器 |
| 内容与展示管理 | 浏览筛选、版本、归属、批量标签／可见性、期限规则 | 当前帖子“在 Studio 中打开”，不保留第二套管理页或批量修改按钮 |
| 分类、模板和标签库 | 创建维护、导入更新、统计和设置 | 使用应用提供的数据辅助当前页面；管理入口跳转应用 |
| 自动转发与其他任务 | 新版本检查、路线、排除、去重、统一队列和活动记录 | 发送当前帖子等上下文，不另跑转发、隐藏、收集任务 |
| 新关注、AI 与既有素材功能 | 配置、分析、复核、数据和任务执行 | 提供“交给 Studio”入口；确需浏览器的举报步骤作为受控辅助，不另做分析或管理系统 |
| Tumblr 网页体验 | 保存需要共享的偏好／结果 | 去广告、隐藏推荐、页面过滤、搜索及输入辅助 |
| 连接与迁移 | 权威数据、备份导入、业务设置和记录 | 连接状态、打开应用、必要的浏览器权限／页面选项、旧数据导出 |

同一业务只实现一次。插件里的快捷入口调用应用已有的能力，显示同一个任务结果，不另建算法、设置、日志或任务队列。网页内选模板是一种就地输入辅助，不是再维护一套模板库；Tumblr 自己的发布按钮仍由 Tumblr 提供。

应用关闭或连接断开时，去广告等纯网页功能可继续，标签辅助可使用明确标注的缓存。需要应用的操作提示打开／连接 Studio，收到应用持久保存的回执后才能显示“已加入任务”；插件不能偷偷恢复独立运行。最终产品不保留“切回插件独立管理”的开关，现有接管开关只作为迁移保护。

旧插件的完整管理页、分类模板管理、批量编辑、独立 AI 和自动任务需要迁移／退役；保留的数据和功能逐项标明去向，尚未迁移的明确列出，不能默默丢失。已有素材能力迁移到应用属于职责调整，不等于扩展新素材库，也不能违反 reblog 创建后正文与标签固定的规则。这一分工是已确认需求，尚未据此改完代码。

## 1. 打开软件

建议默认进入“我的内容”：左侧选择全部或某个管理博客，中央显示作品和图文记录，顶部始终有“写一篇”。保留上次的博客、类别和浏览位置。

上方按创作性质、作品定位、所属课程和记录内容组合筛选；具体名称及标签由用户维护，摄影／写作保留为可扩展的表达形式选项。博客与这些分类分别选择：ARC-V 等主题下既能有作品，也能有绘画过程日记，不能因为帖子带图就自动归为作品。多个筛选条件默认同时满足，例如“同人＋习作＋猹鱼日绘”。

浏览视图以一份内容为单位，合并自己的原帖和关联转发；卡片提示在哪些博客展示。需要检查某个博客实际包含哪些帖子时，切换“在此展示”，逐条显示该博客的原帖和转发。两个视图的筛选含义必须清楚，不能让用户误以为合并卡片等于远端删除了重复帖子。

图片内容支持网格浏览，文字或图文日记支持时间线。打开详情可查看完整图文、标签、管理归属和各副本状态。没有正文或图片缓存时明确显示“需要联网载入”，不能把空白当作原帖内容。

首页只显示轻量提示，例如继续草稿、即将隐藏和需要复核；任务日志与复杂设置放在各自入口。不会因有一条后台错误就遮住正在写的内容。

## 2. 写作与发布

建议流程：选择管理博客 → 直接写文字、插图和排布 → 按需选各维度分类和模板 → 检查预览 → 发布。

- 文字、格式、图片及排布作为完整草稿自动保存到本地；退出后可继续写。通过选择文件、粘贴或拖入文件加入图片。
- 默认直接在可视化编辑区操作图片和文字，提供稳定的拖动与明确的位置操作。Markdown 快捷输入、导入或导出可选，不要求用户维护源码，也不限制 Tumblr 原有的排布能力。
- 标签显示为“通用分类 → 模板标签 → 手动补充”，各段来源清晰；热度排序不能把通用分类挤到后面。
- 发布区一直显示原帖目的地，以及是否会通过规则转发到主博客。被排除的原因用自然语言说明。
- 本地草稿与 Tumblr 草稿分别命名，保存本地草稿不会上传或公开。
- 发布失败保留原稿和图片。结果不明时先核对远端，避免重试造成重复帖子。

示例：在某个主题子博客写一篇绘画过程，选择 `diary`，再选角色模板。若该子博客到主博客的路线排除 `diary`，预览显示“发布到子博客；因 diary 不自动转发到主博客”。排除表示不转发整篇内容。

### 已确认的分类体系（2026-11-06）

采用独立维度组合，不预建“原创习作”“同人正式作品”等复合分类：

| 维度 | 初始选项 | 选择原则 |
|---|---|---|
| 创作性质 | 原创、同人 | 普通人体临摹或观察练习可以都不选 |
| 作品定位 | 习作、正式作品 | 由用户决定，不能根据完成度判断 |
| 所属课程 | 猹鱼日绘、猹鱼速写、tenten人体系统课、文艺复星球中级班 | 保留四个完整名称；非课程作品不选 |
| 记录内容 | 过程记录、学习笔记、日记 | 按实际内容组合，可同时选择 |

**各组都可不选，也允许全部留空后发布。** 课程作业不自动等于习作，习作不等于未完成；课程作业可以是正式原创作品，同人图也可以用于练习。摄影／写作不塞进“原创／同人”，作为表达形式的可扩展选项保留。分组、选项和顺序均可维护，不把课程名称写死在通用逻辑中。

界面名称与真正发到 Tumblr 的标签分别保存。“同人”可沿用 `fanart`，“日记”沿用 `diary`，课程可使用完整中文名；其他实际标签可以配置，并在发布预览中明确列出。最终顺序仍为“通用分类 → 模板 → 手动补充”，分类内部按设定的组和选项顺序排列。分类和 ARC-V 模板都带 `fanart` 时只输出一次，保留在分类靠前的位置。

例如：“同人＋习作＋猹鱼日绘”后再选圈子／角色模板；“原创＋正式作品＋文艺复星球中级班”描述正式的课程作品；复盘可选“学习笔记＋猹鱼速写”，展示练习图时再加“习作”。

组合筛选必须支持多个完整标签同时满足，不能只用一个文本搜索框代替。“归我管理”筛选当前原帖／作品分类；“在此展示”筛选每条实际帖子的标签，同一条历史 reblog 必须自己满足全部条件，不能拼接不同版本的标签或套用原帖现在的分类。

改分类或标签不产生内容新版本，不触发再次转发，也不回写已有 reblog。以后因正文更新再次转发时，才使用当时的标签。迁移平铺分类时保留原有 ID、标签、顺序、自定义项和草稿选择；无法明确分组的项目暂放“未分组”，不自动改远端帖子。

这部分现已确认为需求，尚待完成分组存储、编辑界面、组合筛选和迁移。当前软件的平铺多选、标签去重和单标签查询不等于已实现上述流程。

### 图片编排的具体提案

下面是针对已确认痛点的界面提案，按钮名称、布局预设仍可讨论：

目标覆盖 Tumblr 实际支持的正常图文排布，不需要用户先选定只使用并排或只使用图文穿插。实现时核对各项功能的读取、保留、新建和编辑能力，区分“接口不支持”和“尚未实现”。

1. **直接插入到位置。** 在一段文字前后点“插入图片”，或者把图片粘贴到当前插入位置；多张图片先在缩略图列表中确认顺序。
2. **选图后点排布。** 选择相邻图片，点击“一张一行”或可支持的并排预设；不需要先拖到某个难以命中的边缘。每行支持的数量以实际发布验证为准。
3. **用按钮改位置。** 每张图片可前移、后移、移到指定段落前后；整行可上移、下移，同行内也可换序。跨文字段落合并时明确展示文字会留在哪里。
4. **替换不拆版。** 在原位置换一张图，保持该位置的说明和布局；替代文本应提醒检查。删除、移动、并排与替换均可撤销。
5. **发布过程中布局也稳定。** 当前图片随创建帖子请求一起上传，发布时冻结草稿版本和图片对应关系；缺失或无效图片定位到原位置修复。请求失败保留原稿，回执不明先核对远端，不能直接重发。关闭重开仍保持图文顺序和并排关系；以后若改为独立上传，也不能按完成先后排列图片。

拖动可作为附加快捷方式。核心验收是：完全不用拖动，也能完成图文穿插、并排、换序和纠错。排布调整不默认裁切源图片，也不把多张图合成一张来假装支持并排。

### 记住习惯，保留当前选择

按博客保存常用类别、模板及可复用的角色组合，写下一篇时允许沿用。切换博客时显示对应默认值，不静默覆盖已经写好的选择。角色组合不自动视为每篇内容都一样，可通过具名预设选择。

发布目的地、可见性和自动转发结果始终可见。更改记忆的默认设置只影响后续新内容，不回写旧帖或批量修改现有草稿。

## 3. 子博客统一管理

已确认：主博客先发布、随后由自己的一个子博客转发的内容，可以归该子博客管理。原作者、原始链接和原帖所在博客保留。

详情侧栏示例（虚构）：

| 项目 | 显示内容 |
|---|---|
| 归属 | 由主题子博客管理 |
| 原帖 | 主博客 · 当前公开 · 发布于某日 |
| 我的转发 | 主题子博客 · 当前隐藏 · 转发于某日 |
| 标签 | 维护当前原帖和下次转发的类别与模板；旧转发标签作为历史快照保留 |
| 展示 | 原帖和转发逐项显示期限、例外、实际状态 |

原帖藏在主博客也能从子博客管理页找到并修改。页面上的“主账号发布者”不是判断原帖位置的依据，必须使用真实的转发关系。

已有转发独立保留创建时的正文、图片排布和有序标签，软件不再修改这些字段。原帖内容更新后，符合已启用路线的新版本另建一条 reblog，旧版保留；只改标签不产生新版本，也不再次转发。逻辑上的“一份内容”可以包含多个版本、每版多个转发实例；详情显示各自实际内容和标签，不能统一显示最新原帖。管理页的正文／标签修改指向实际原帖，预览明确排除历史转发；公开／隐藏按选定实例或展示规则另外执行。

素材收集到素材博客不接管作者归属，也遵守创建后正文与标签固定的规则。两个专题子博客同时接管的少见情况已按用户要求延后：保留现状、标记待处理，不自动选择赢家；同一子博客收到多个版本仍只算一个管理者。

## 4. 旧帖与长期公开

### 不同转发版本的日常维护

在应用的作品详情增加统一的“版本与转发”入口，任何一条原帖或转发都能回到这里，不必来回找不同博客。内容卡片提示版本数和待处理项。

- 按内容版本列出各博客的转发，显示缩略图、链接、转发时间、公开／隐藏状态、长期公开例外和任务结果；“原帖最新内容版”与“该博客最新已核实转发”分开标记。
- 选两版比较正文、图片及排布，标签差异单独列出；缺少快照或媒体时如实显示无法比较。只改标签仍不产生新版本。
- 按博客、版本和状态筛选，单选或批量公开、隐藏、长期公开、回到规则或删除转发；一次预览列清涉及的帖子及例外，删除明确确认，实际原帖不默认纳入。
- 提供一次性的“保留最新公开版，隐藏旧公开版”：各博客分别计算，保留最新已核实公开转发，尊重长期公开例外。新版还没发成功或尚未公开时不先藏旧版，不自动发布新版，也不在以后每次新版本到来时自动清理。
- 版本可加本地简称／备注，不改 Tumblr 正文和标签；缺少当前版、分发失败和结果未知可直接进入对应处理，补发仍遵守去重和排除规则。删掉的版本转发保留删除记录，不自动重建。

插件只打开应用中的这份详情。已有版本列表不等于这些维护操作全部完成；具体规则及验收见 [REBLOG_POLICY.md 第 2.1 节](REBLOG_POLICY.md#21-在应用里集中维护各版本)。

已确认：自动隐藏按发布时间计算，用于减少主页积累的旧帖，且必须能隐藏原帖。发生转发本身不会触发隐藏。

每个受管理的远端帖子显示一种策略：

| 策略 | 行为 |
|---|---|
| 按期限展示 | 满足已启用的天数规则后隐藏 |
| 长期公开 | 用户选择的持续例外，不因热度变化、重启或规则修改失效 |
| 保持隐藏 | 不被自动恢复公开 |

建议提供“即将隐藏”视图，可按剩余天数或最近同步的热度排序，单选或批量设为“长期公开”。时间窗口可选，初始建议七天。热度显示同步时间，不冒充实时数据。关联副本的热度不能直接相加造成重复统计；以选定原帖的值为主，副本值分开展示。

用户可以直接把热度高或个人喜欢的帖子保留，不需要解释原因，也不要求达到某个热度阈值。一次选择长期有效。关闭规则或延长期限不会自行把以前隐藏的帖子全部重新公开。

**仍待选择的偏好已经做成配置，不阻塞其他设计：**

- 按博客分别设置：原帖与自己的转发分别计算各自的展示期限。
- 同组一起隐藏：使用原帖的到期时间，操作用户指定的自有副本；逐个尊重“长期公开”等手动例外。

首次启用时明确选择范围并预览受影响的帖子，不默认执行未选择的跨博客隐藏。别人持有的转发不属于可操作范围。具体时间与冲突处理见技术主稿。

只隐藏原帖时，界面说明“仅隐藏这条帖子，已有转发不受影响”。如果要隐藏自己博客上的所有相关帖子，就逐条隐藏原帖与自己的转发，可以手动批量完成，也可以配置同组规则；这不意味着用户必须采用同组规则。有长期公开例外、操作失败或同步未完成时，不能声称整组已全部隐藏。

旧版 A38 将这一平台机制写成待发现的实测问题，现已撤回。后续只检查应用自己的实例管理与操作范围，不为证明已知机制反复在真实账户发帖。

第 0 阶段记录了公开页面生效延迟：不同轮次约为 1 秒与 70 秒，不能承诺立即隐藏。当前软件核对的是帖子自身状态，尚未实现访客可见性检查，因此只能显示“私密状态已确认；访客可见性未检查”，不能暗示正在后台检查。设计中的独立访客检查仍列为缺口；实现后记录检查时间，暂时仍可见时继续核对，不靠反复提交隐藏操作催促生效。

## 5. 自动转发

每条路线直观显示“从哪里 → 到哪里”，排除哪些完整标签、是否处理历史内容，以及最近的结果。

新增原帖及已转发原帖的内容新版本沿已启用路线分发；未启用路线时只提示可再次转发。按“源帖＋内容版本＋目标博客”去重，目标上的旧版不能挡住新版，相同内容版本也不能因重扫或改标签而再次创建。带排除标签就跳过该次分发，主博客本来已有实际原帖则不再往主博客回转。新建路线和迁移先建基线，不默认倾倒历史帖子，历史补发单独预览。

检查更新不能只读新发布的帖子，还要检查已转发源帖的内容变化。标签、阅读量、可见性或管理归属变化不算内容版本。发送前读取当前标签判断排除资格，并冻结该次提交的标签；后来改标签不影响已创建的快照。再次转发从真实更新源取内容，不从旧 reblog 制造“新版”。回执不明或版本不符时先核对，不能改写旧版或盲目重发。用户删除的某一版不自动重建，但之后的内容新版本仍可按路线转发。

已验证私密原帖不能转发。明确需要“转发后隐藏”的任务先完成转发，再隐藏原帖；不为补转发自动把私密帖子重新公开。用户直接要求隐藏时优先执行，无法完成的分发另列结果。

更改排除标签只影响后续转发资格，不改写已有转发的正文和标签，不触发已完成或已跳过版本自动重发。已有转发的隐藏／删除是另行明确的操作，不把“以后不转发 diary”误解成“删掉所有旧日记”。

## 6. 新关注保护

日常自动检查有证据的垃圾引流、诈骗或重复骚扰行为。正常成人作者、同人作者、潜水号、空白号，以及单纯有外链的账号，不因此被处理。

界面以结果为主：已拉黑、待举报、需复核。点开才看具体证据。用户标记“正常账号”后持久记住，撤销相关待执行任务；如已误拉黑，提供解除拉黑操作并核对结果。

目标中的“自动拉黑”和“自动举报”分别开关、分别验证。当前复核版不启用这两项：手动拉黑／解除拉黑后核对拉黑列表，真实账号端到端验证仍待完成；举报在 Tumblr 菜单进行，用户确认前一直待举报，确认后也应区别于软件取得提交回执。后续浏览器自动举报需单独验证，不能把打开页面当作完成举报。具体能力验证、证据策略、纠错和验收见反骚扰详稿。

## 7. 本地保存与范围限制

AI 配置的便利目标：应用可从 CC Switch 选择已有配置，自动取得可用的接口地址、模型和密钥，减少重复手填；手动配置保留作备用。读取配置与接口兼容要分别验证，字段缺失或协议／模型不支持时明确说明，不偷偷换供应商，也不在插件里另配一份。当前代码仍是手填地址、模型和密钥，尚未接入 CC Switch；具体待实现要求见技术主稿第 4.4 节。

为保证写作可靠，完整的文字、格式、图片排布、附件、草稿修订和发布关联需要本地持久保存，这是实现方案的基础。Markdown 可作为可选导入／导出格式，不能成为丢失图片排布的原因。完整下载已有远端历史和原始媒体尚未由用户确认，设计为可选的独立归档范围，不在首次同步时静默下载整个账户。

用户已明确暂不扩展素材库、参考与创作关联或新的素材 AI 功能。已有收集、整理与 AI 能力按最新分工归应用负责，插件仅保留网页快捷入口；迁移清单逐项说明可用与待迁移状态，不保留第二套独立插件业务。保护已有素材标签、AI 说明、收藏和模板数据，素材博客也不自动加入个人内容分发；职责迁移不等于授权新功能或修改历史 reblog。

备份至少包含数据库和本地草稿附件，并能在新目录恢复。远端缩略图缓存不标称完整原图备份。是否发展成完整素材／创作资料库，可以以后增加，不影响现在的写作与管理主线。

## 8. 实现边界和交付顺序

已确认需求先实现；以下采用明确的方案或配置推进：

| 项目 | 当前处理 |
|---|---|
| 原帖与转发隐藏范围 | 支持独立／同组配置，启用时显式选择 |
| 自动隐藏例外 | 用户手动长期公开，持续保存 |
| 每个博客的用途 | 配置为个人分享、专题分享、素材或未分类；未分类不自动加入路线 |
| 完整历史归档 | 可选后续范围；新写内容先可靠落地 |
| 新关注自动化 | 按详稿验证后启用，未知证据不自动处理 |
| 图片编排 | 优先做稳定、可撤销、不依赖拖动的编排；具体布局交互继续讨论 |
| 记录收集／关注流 | 用户尚未考虑，不纳入首版；编辑自动保存照常提供 |
| 应用与插件 | 应用是本体；插件只做浏览器辅助及应用入口，移除重复业务 |
| 素材扩展 | 不扩展新功能；保护既有数据，保留能力按分工迁移应用 |
| 翻译写作辅助 | 不纳入范围 |
| 公开主题 | 首版之外 |
| 两个子博客接管 | 延后复杂处理 |

Claude 先验证浏览器关闭后的授权、发布与管理能力，再实现本地数据和任务系统、内容归属与展示、可视化编辑和稳定图片编排、发布及转发、新关注保护。设计与技术验证可以继续，不需要逐个等用户决定界面颜色、默认筛选或常用图片排布等可逆细节。账户测试应使用明确授权的测试范围。

[第 0 阶段结果](STAGE0_RESULTS.md)已提供，第 1–4 阶段也已有代码。接下来应按主稿 A01–A57、全局转发规则 R01–R17 及反骚扰验收场景逐项记录通过、受阻、延后或未运行，并注明证据；已有 R01–R11 的测试不能替代新增版本维护场景。基础层仍需核对完整帖子编辑、写后轮询、独立副本状态、分页完成标记、持久任务依赖及旋转令牌存储。拉黑／解除拉黑和旧格式编辑的真实能力缺口继续限制相应功能上线；社区标签保留已于 2026-11-06 对两种标签来源验证通过。

设计稿不是已实现软件。交付时应附实际能力结果、验收结果和仍不可用的操作；不得把缺少举报能力或独立运行能力描述成已完成。
