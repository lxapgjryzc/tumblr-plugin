# 内容页与筛选器改进需求

日期：2026-11-07。供 Claude 实现。关联主稿：[DESKTOP_PRODUCT_SPEC.md](DESKTOP_PRODUCT_SPEC.md) 第 5、6.3、7.2 节。

**用户反馈：内容标签页操作和界面不顺手；“分类与标签”本质上是筛选器，现有实现不合格。** 本文把反馈整理为改进建议、具体交互及验收标准。用户已明确要求改进方向；下文的布局、默认逻辑和优先级是本次设计建议，不冒充逐项经用户确认的决定。本文仅交接需求，未修改应用实现。

本次依据：检查运行中的桌面应用“内容”页及“分类与标签”弹窗，并阅读 renderer、查询接口和既有产品约定。实际窗口只进行了查看、打开和取消筛选弹窗；未提交筛选、修改帖子或触发批量任务。代码推导的问题与已观察的界面问题分开记录。账户名称、帖子内容和截图不写入仓库。下文数量和示例均为虚构。

**与既有约定的关系：** 保留作品／实际帖子两种视角、可选的分类维度、完整标签匹配及独立的批量操作。建议用“分类组内任一、组间全部；每组可切换为全部”替代旧的所有勾选一律 AND；旧条件迁移仍保留原 AND 含义。reblog 行为遵守 [REBLOG_POLICY.md](REBLOG_POLICY.md) 顶部的晚间修订：自己的原帖标签会同步到自己的转发，正文及版本仍固定；别人的转发和素材标签不据此重写。筛选按实际已读到的数据判断，不能假装待同步标签已经写入。

## 1. 现状问题与改进目标

| 问题 | 证据 | 对用户的影响／应改成什么 |
|---|---|---|
| 筛选入口叫“分类与标签”，提交按钮叫“执行” | 实际窗口、`PostsPage.tagFilter()`、i18n | 容易误解为管理或修改标签。入口统一为“筛选”，分类与标签是其中一部分；筛选不使用执行任务的文案 |
| 弹窗遮住结果，选完关闭才知道有没有找到 | 实际窗口 | 改成可收起的侧栏；结果和生效条件同时可见 |
| 所有选择只能同时满足 | `tagFilter()`、`api.posts()` | 无法查“课程甲或课程乙”“排除日记”；增加可见的任一／全部／排除语义 |
| 其他标签需要记住拼写后输入逗号和回车 | 实际窗口、`tagFilter()` | 提供本地已有标签候选、搜索、数量及键盘选择；不要求记忆内部英文标签 |
| 输入但未回车就点“执行”，文本未进入 `chosen` | `tagFilter()` 的输入和提交路径，代码推导 | 输入不能悄悄丢失；支持直接添加及关闭时保留未完成文本 |
| 组内所有选项铺开，缺少搜索和命中反馈 | 实际窗口 | 分类按组折叠／展开，长列表可搜索；显示结果数、零结果与缺少数据的区别 |
| “全部博客”实际默认传入 `share: true` | `PostsPage.load()`、`api.posts()` | 标签与范围不一致；明确“分享博客”与“全部博客（含素材等）” |
| “归我管理／在此展示／即将隐藏”并列，但含义不同 | 实际窗口、`toolbar()` | 前两者是数据视角，后者是筛选条件；视角与快捷筛选分层 |
| 改筛选、博客或视角没有清空 `sel` | `toolbar()`、`load()`，代码推导 | 看不见的旧选项可能继续参与操作；查询范围改变时解除选择并明确告知 |
| 普通点击会随“是否已有选择”改变作用 | `grid()` | 同一操作有时打开、有时选中；固定卡片打开、复选框选择的分工 |
| 卡片看不到分类／标签，图片统一裁成 4:3 | 实际窗口、`grid()`、CSS | 难以解释命中、辨认完整作品；增加命中分类、完整图预览及图片数量 |
| 只显示总数和“全选本页”，没有已加载数、同步覆盖 | 实际窗口、`load()`、`selectAll()` | 60 条已加载结果容易被当成全部；区分已加载、全部匹配和整个远端博客 |
| 即将隐藏走另一接口，搜索和标签控件被藏起 | `load()`、`toolbar()` | 进入后无法继续组合分类条件；统一查询条件并显示快捷筛选的效果 |
| 重新进入页会重置加载数与滚动；异步查询无过期响应保护 | `render()`、`load()`、`App.go()`，代码推导 | 浏览被打断、旧请求可能覆盖新条件；保留浏览位置，并只渲染最新查询结果 |

目标流程：**选范围 → 逐步缩小结果 → 看清命中原因 → 打开查看 → 明确选择 → 一次预览后批量处理。** 筛选本身只读取本地已同步数据，不创建任务、不修改分类配置、不改变任何帖子的标签或可见性。

## 2. 内容页布局与操作

### 2.1 顶部只放高频操作

建议宽窗口布局如下。沿用现有应用侧边导航和主题，不要求重做全站视觉风格。

```text
内容   [作品 | 博客帖子]                         同步覆盖／更新时间
[管理博客或所在博客 ▾] [搜索内容…………] [筛选 3] [排序 ▾] [网格 | 列表]
快捷：全部内容  即将隐藏  按规则隐藏  长期公开  待处理
已生效：创作性质=同人 ×  课程=甲或乙 ×  排除=#diary ×      清空条件
┌ 筛选（可收起） ───────┬ 找到 128 个作品 · 已加载 60 个 ────────────┐
│ 分类                │ [全选已加载的 60 个]                         │
│ 创作性质  [任一 ▾]   │ 内容卡片／列表                               │
│ □ 原创  ☑ 同人       │ 分类 · 命中标签 · 状态 · 博客／版本             │
│ 所属课程  [任一 ▾]   │                                             │
│ ☑ 课程甲  ☑ 课程乙   │                                             │
│ 标签 [搜索已有标签]  │                                             │
│ 包含 [全部 | 任一]   │                                             │
│ 排除 #diary         │                                             │
│ 更多：状态、日期…    │                                             │
└─────────────────────┴─────────────────────────────────────────────┘
选择后：[已选 12 个作品／12 条原帖] [改标签] [可见性 ▾] [更多 ▾] [取消选择]
```

- 在内容区域内提供约 260–300 px 的筛选侧栏，展开后结果仍可浏览、滚动。首次默认收起，记住用户的展开状态；有条件时始终显示数量和条件条。
- 980 px 最小窗口下允许转为可收起的顶部筛选区，避免同时挤出三个窄栏。打开详情时可暂时收起筛选，关闭详情恢复原布局。不要用遮住全部结果的全屏筛选弹窗。
- 条件条按组汇总，显示中文分类名称、任一／全部／排除及日期范围；可单项移除。多条件折叠为“另 N 项”，仍能展开查看全部生效条件。
- “清空条件”清除分类、标签、文本、状态、时间、策略及快捷条件，保留当前视角、博客范围、排序和布局；条件为空后文案改为“当前范围内全部内容”。博客范围是明确的上层范围，不被悄悄改成所有博客。
- 无选中项时不常驻一整条批量命令和长快捷键说明；保留选择入口及简短帮助。选中后显示固定位置的操作条，常用操作优先，低频操作进入菜单。
- 普通选项即时生效，约 200–300 ms 合并连续输入；不再需要在筛选后点“执行”。加载中保留原结果并标为正在更新，显示最新条件，禁止把旧结果当成新结果进行全选／提交操作。

### 2.2 视角和范围要能直接读懂

| 控件／信息 | 作品（原“归我管理”） | 博客帖子（原“在此展示”） |
|---|---|---|
| 一行／一张卡片代表 | 一个逻辑作品，以 `item_id` 去重 | 一条实际帖子，以 `blog + id` 区分，旧版本不会折叠消失 |
| 博客选择器标签 | 管理博客 | 所在博客 |
| 分类、内容、状态、日期的依据 | 自有作品以当前实际原帖为准，明确“原帖状态／原帖发布时间” | 当前这一条帖子的已观察标签、正文、状态及发布时间／转发时间 |
| 计数 | N 个作品 | N 条帖子 |
| 卡片主要身份 | 管理博客；原帖在其他博客时补充原帖位置 | 所在博客、原帖／转发、来源及内容版本 |
| 默认批量目标 | 所选作品的自有原帖，预览中展开为具体帖子 | 勾选的具体帖子；标签编辑只处理其中的自有原帖 |

- 作品视图不从任意转发借用当前原帖的分类或状态。原帖未读到／已删除时只保留一张“原帖信息缺失”的作品卡；需要该字段的条件不能误命中，依赖原帖的修改不可用。
- 若保留他人作品的聚合浏览，标明“外部来源”，仅显示可核实的来源信息；来源缺失时分类为未知。转发自身的分类和素材标签应在“博客帖子”视角筛选。
- 默认博客范围可以保持现有分享博客范围，但必须写“分享博客”；真正的“全部博客”涵盖所有已连接博客并标注角色。素材在该范围中可见，不要求扩展素材产品能力。
- 状态、异常和日期按当前视角解释；“原帖隐藏”不代表其他博客的转发也隐藏。保留既有原帖／转发身份、管理归属及版本规则。
- 从主页进入“待处理”必须显示“待处理”条件及退出入口，不能让隐藏的 `review` 状态吞掉其他控件的效果。

## 3. 一个完整的筛选器

### 3.1 可组合的维度

| 维度 | 行为 |
|---|---|
| 分类 | 使用配置的分组和选项，显示名称与实际标签分开；不在此创建、编辑或删除分类 |
| 标签 | 包含全部、包含任一、排除任一；支持模板标签和手动标签，不局限于通用分类 |
| 内容搜索 | 搜索已同步的标题／正文摘要与标签，提示具体覆盖；精确标签条件通过标签候选添加，不能混同模糊文字搜索 |
| 远端状态 | 公开、隐藏、Tumblr 草稿、队列；尚未发送的本地草稿仍走写作页，不能混算 |
| 帖子类型 | 原帖／转发，仅在博客帖子视角生效；切换到作品视角移除该条件并提示 |
| 时间 | 最近 7／30／90 天及自定起止日期。使用当前视角标明的时间字段；结束日期包含当日，按应用当前时区转换区间，未知日期不伪造 |
| 展示策略／隐藏原因 | 长期公开、保持隐藏、按规则；按规则隐藏与手动隐藏分别匹配，来源证据不足显示“原因未知” |
| 处理状态 | 管理待复核、冲突、任务待处理／失败／结果未知；在当前视角汇总为作品或准确帖子，不拿别的实例状态替换本实例状态 |
| 即将隐藏 | 预设时间窗 7 天，支持 3／7／14 天和自定义；逾期未完成与未来将隐藏分开标记，可继续组合分类、标签等条件 |

快捷筛选只是预填上述条件。启用“即将隐藏”时明确切换到博客帖子视角，以实际到期实例为单位；保留适用的分类／标签／搜索条件，将状态设为公开并在条件条展示。与之冲突的旧条件要明确替换和提示，不静默忽略。退出快捷筛选移除它引入的条件并保留其余条件。切换视角不能改变任何远端状态或开启自动规则。

### 3.2 分类的组合逻辑

**建议默认：同一分类组内满足任一，不同组之间同时满足。** 每组都有“满足任一／满足全部”开关；只有选中至少两项时需要强调该开关，但当前含义始终可读。没有选择的组不构成限制，不推断用户应选哪个类别。

例如：

```text
创作性质：同人
作品定位：习作
所属课程：课程甲、课程乙（满足任一）
记录内容：过程记录、日记（满足全部）
排除标签：commission

fanart AND art study AND (课程甲 OR 课程乙)
AND wip AND diary AND NOT commission
```

- 各组可添加排除选项，含任一被排除标签就排除该候选；排除是独立可见的列表／操作，不能依赖右键、双击或颜色循环猜状态。
- 标签区有一个“包含”列表（全部／任一，默认全部）和一个“排除”列表。分类条件、标签包含、标签排除以及其他维度之间均为 AND。无需首期做任意嵌套布尔表达式编辑器。
- 同一规范化标签不能同时包含和排除；改为相反用途时明确提示并替换旧用途。跨分类／手动标签重复也要识别冲突和去重，不能让互相抵消的条件悄悄返回零条。
- 每组提供“未设置本组分类”；它与该组的正向选项互斥。标签区另提供“无任何标签”。“没有课程”“没有标签”“原帖数据未知”是三种不同情况。
- 未设置本组分类＝数据已知，且未含当前该组任何配置标签；不代表用户必须补分类。组里没有配置项时不提供这个无意义条件。
- 数据未知不等于空列表。只有排除条件、选择“无标签”或“未设置”时，也不能把缺失的原帖数据当作满足条件；未知候选单列提示，可用“信息缺失”条件专门查找。
- 分类别名只是显示名。匹配必须落到实际完整标签；同名分类不能凭显示名合并。修改分类映射不改旧帖，也不为旧帖虚构命中。

**匹配规范：** 查询、标签候选、计数和选择范围统一复用项目的 `core.norm/key` 语义，双方都规范化（解码可解码的编码、去掉开头 `#`、整理空白、大小写不敏感）。原始文本用于显示，过滤不重写帖子。`art` 不匹配 `fanart`，`diary` 不匹配 `diary notes`；中日文、空格、emoji、编码字符、`%`／`_` 都按其真实字符含义处理，不能意外变成 SQL 通配符。正文模糊搜索同样以用户文本为字面搜索，不暴露 SQL 模式语法。

### 3.3 标签选择和结果反馈

- 输入支持分类显示名和实际标签搜索；候选来自当前范围的全部已同步记录及分类配置，不只扫描已加载的 60 张卡片。候选展示“同人 · #fanart”，手动标签展示原文字形。
- 支持上下箭头、Enter、点击候选和明确的“添加”按钮；中文输入法组合期间的 Enter 不提交。粘贴以英文逗号、中文逗号或换行分隔，标签内部空格保留。明确提示这些分隔规则。
- 未完成的输入保留在面板状态中，切换组／收起侧栏／打开详情后仍在。输入文字本身不会悄悄加入条件；无候选时提供“使用完整标签 #…”并提示暂无已知匹配。不能因没按回车而把文字清空。
- 候选可按名称或本地使用量排序。查标签名称只缩小候选列表，不能同时修改内容搜索。分类配置与标签库中相同规范化标签合并展示。
- 结果区显示“匹配 N 个作品／N 条帖子；已加载 M”，同步不完整时补充“仅在已同步内容中查找”和覆盖／最近成功同步信息；读取失败显示“无法获取”，不能显示零条。筛选不会自动启动全量远端同步。
- 建议提供候选的“加入后 N 条”预估：基于完整查询复制一份，按当前任一／全部／排除模式加入该候选再计数。该数字是加入后的结果总数，不冒充标签全站热度。已选项不重复显示加入预估；未知时显示“—”，过期响应不能更新当前数字。
- 预估和主结果都使用当前视角的去重单位及同一数据快照。零匹配选项仍可选，不能因为当前其他条件很窄就让用户无法表达它。
- 零结果保留全部条件和输入，允许单独去掉条件、撤销上次修改或清空条件。明确区分“条件无匹配”“尚未同步”“请求失败”三种状态。

### 3.4 记住查询，避免重做

- 离开内容页再返回、打开／关闭详情后恢复查询、排序、布局、展开组、已加载范围和滚动锚点。重启恢复最后一次已生效查询和布局，批量选择不跨重启恢复。
- 建议第二批支持具名“保存筛选”，例如“课程习作”“未分类”“即将隐藏的同人”；保存查询而非帖子列表，重开按最新已同步数据重算。不保存批量选择，不执行任务。
- 保存项使用稳定分类 ID、当时规范化标签及查询版本；改名可以更新显示名，标签映射变化或分类删除则标出旧映射，保留原标签条件，等用户明确更新，不能静默改变保存项的含义。
- 原有 `tags: []` 条件迁移为标签“包含全部”，不能因为新版组内默认任一而扩大旧查询。分类配置、草稿选择、发布默认值均不随筛选迁移而改动。

## 4. 选择范围和批量操作

### 4.1 选择不会跟着隐藏状态走

- 卡片／行普通点击始终打开详情；复选框始终选择。Ctrl+点击可作选择快捷方式，Shift+复选框选择连续范围，Ctrl+A 仅选择当前已加载结果，Esc 退出选择。拖选只能是补充，不能妨碍浏览或成为唯一操作途径。
- 复选框在键盘聚焦或进入选择模式时清晰可见；图标具有可访问名称，不能只靠 `↗` 暗示详情与外链。文本框内 Ctrl+A 只选文字，弹出层内快捷键不穿透内容页。
- 博客、视角、文本、分类、标签、日期、状态或快捷条件改变并生效时，清空选择及范围锚点，显示“筛选已改变，已取消选择 N 项”。排序、网格／列表切换、打开详情不清空选择。
- 查询更新中不能全选旧结果。后台同步不自动加入新选项；原选项删除、失去权限或不再匹配时标明失效数量，不能继续悄悄执行。预览重新核实并列出跳过原因。
- 离开内容页解除选择，返回恢复浏览上下文；收起筛选／查看同一页内详情不解除。此规则与“保持筛选和位置”分别实现。

### 4.2 已加载与全部匹配是两个明确动作

1. 按钮写“全选已加载的 60 条”，Ctrl+A 同义，不再称“全选本页”。只加载了 60／128 条时，必须看得出还有 68 条。
2. 已全选加载部分后，提供“选择全部 128 条匹配结果”。通过服务端同一查询解析全部本地匹配身份，不靠不断增加 limit 或把未显示 DOM 当数据源。
3. 在选择全部时冻结当时的匹配 ID 集合及查询版本。后续新增的匹配项不自动加入；预览和提交引用同一集合。超过内部容量时给分批方案与数量，不静默截断成 60 条或任意上限。
4. 作品选择保留 `item_id`；帖子选择保留 `blog + id`。作品不能因为有三条转发就计为三次选择，缺失原帖也不能退而修改任意转发。
5. “加入我的关联帖子”改为展开选择范围的明确操作：先列出将增加的博客、原帖／转发、版本与数量，用户勾选加入；默认不扩展。跨出当前筛选范围的关联项在操作条标为“额外关联 N 条”并可查看／移除，不能藏在看不见的 Map 中。

### 4.3 一次清晰的操作预览

- 标签操作显示将修改的原帖、增删标签及逐项差异；选中的转发不会直接改标签，也不能偷偷转成“修改它的原帖”。作品视角映射到自有原帖是明确的默认规则；帖子视角若只选转发，提示去原帖处理。
- 自己原帖的转发可能依照现有标签同步规则随后更新：预览说明这项既有影响及适用范围，任务结果区分原帖已改、转发同步待处理／完成。不能继续笼统地写“所有快照标签保持不变”。此需求不新增或开启自动同步规则。
- 公开、隐藏、长期公开、回到规则列出具体目标及影响，实际帖子和逻辑作品分别计数；关联帖子不默认包括。长期公开可能使私密帖子公开，回到规则可能重新进入到期处理，不能当成没有远端影响的装饰性选项。
- 预览可逐项查看目标、已符合、不可编辑、失效、未纳入关联和待核实项。只需一次面向该批次的确认，复用现有持久任务队列和能力门槛；筛选动作本身没有确认。
- 提交反馈链接到这一个批次的进度；不以 Toast“已加入队列”冒充改帖完成。结果更新保持当前浏览位置，失败项能重试或查看原因。不要刷新整页让用户重新筛选。

## 5. 内容卡片与详情更适合日常浏览

- 提供网格／列表两种布局。网格默认，建议有舒适／紧凑密度；列表适合批量看分类、时间、状态和版本，二者共用同一查询与选择。
- 卡片至少有缩略图或文字摘要、管理／所在博客、明确含义的日期、远端状态、分类摘要和命中标签。当前查询命中的分类优先展示，其他标签折叠为“+N”；点击分类的明确筛选入口可追加条件，点击标签正文不应删除标签。
- 区分“原帖公开／隐藏”与“转发公开／隐藏”，长期公开、按规则隐藏、即将隐藏作为次要状态；多版本显示版本号／数量，任务异常才醒目提示。notes 标明观测时间，不合并原帖与转发互动数。
- 多图卡片显示图片数量并提供查看整组入口。提供完整图预览（`contain` 等方案），不把所有竖图或长图永久裁掉；窄卡片中博客和日期分行，不相互挤成一串省略号。
- 卡片名称、操作和已选状态不只靠颜色传达，检查浅／深色主题以及 980×640、1380×900 下的可读性与按钮可达性。
- 详情优先使用右侧面板，按“内容／标签 → 实际帖子与状态 → 版本与转发”组织；大图可另开预览。窄窗口可暂占内容区，关闭恢复原卡片位置。
- 从博客帖子进入时必须定位并高亮该 `blog + id` 及其内容版本，展示这一实例的图片／正文／标签；不能像当前 `members[0]` 缩略图路径那样误拿另一实例代表它。
- 保留上一条／下一条（沿当前结果顺序）和明确的“在 Tumblr 打开”。管理归属修改后在同一面板更新，不叠出第二层相同详情。关闭面板后焦点回到来源卡片。

## 6. 实现边界与优先级

### 第一批：让筛选可信、操作一致

必须一起完成：视角和博客范围文案；可收起筛选区与生效条件条；分类组内任一／全部、跨组 AND、排除；可搜索标签候选；未设置／未知的区分；准确计数与同步覆盖；统一即将隐藏查询；过期响应保护；选择清理与明确批量范围；卡片显示分类；详情定位正确实例与返回位置。不能只换按钮颜色和间距就报本批完成。

### 第二批：减少重复操作、提高浏览效率

具名保存筛选及迁移、候选“加入后”计数、网格／列表与密度、完整图预览和连续浏览。它们仍是本次建议，分批交付时逐项标记未完成，不以第一批代替完整建议集。

### 实现提示（不是限定技术方案）

| 位置 | 需要解决的职责 |
|---|---|
| [renderer/pages/posts.js](../desktop/src/renderer/pages/posts.js) | 分离查询、加载、选择、详情状态；替代 `tagFilter()` 大弹窗，修正卡片点击与特殊视图行为 |
| [service/api.js](../desktop/src/service/api.js) 的 `posts`／`expiring` | 统一解析查询对象、分类匹配、未知值、作品去重、总数、分面计数与全部匹配身份；不能只在已加载卡片上筛选 |

查询列表、总数、候选计数、全部匹配选择必须用同一份查询定义与数据范围。旧接口可兼容，但不能让 `posts` 和 `expiring` 各自遗漏条件。排序加稳定的身份次序处理同时间／同 notes 的记录，避免分页重漏。

每次查询带递增标识；只允许最新查询更新列表、数量、加载态和错误。取消请求是优化，丢弃过期响应才是正确性要求。切换页面后旧请求不得写入新页面；中文输入期间不发半截条件。后台刷新尽量保持卡片身份、焦点、详情和滚动锚点，已展开页面不能每次退回 60 条。

本轮不重写发布编辑器、不新增标签管理系统、不修改分类配置、不新增自动规则；筛选结果和预览不能成为改帖的隐式授权。继续遵守现有队列、快照正文保护、自己的转发标签同步和社区标签能力约定。
