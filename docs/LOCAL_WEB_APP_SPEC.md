**功能验收补充（2026-11-07）：** [FUNCTIONAL_WORKFLOWS_SPEC.md](FUNCTIONAL_WORKFLOWS_SPEC.md) 定义本次确认的连贯编辑与互动体验。LW 通过只证明运行迁移，完整产品还须通过业务及 FW01–FW12。默认本地网页不变；具体官网能力若需额外适配，由实现者基于验证提出，不为保活常驻浏览器，不提前承诺无浏览器回复或私信。

用户的目的：不用为了后台任务一直开着 Chrome，减少平时的内存占用；需要编辑、管理时可以打开浏览器。已确认采用 **独立本地后台＋按需打开的本地网页界面**。用户另已明确：**Chrome profile1 用于日常工作，profile10 用于 AI agent 测试，不能串用。** 启动入口、通信方式等下文细节是为落实这些选择提出的实现要求／建议，不冒充用户逐项指定的技术选型。

## 1. 确定的产品形态

| 部分 | 职责及运行时机 |
|---|---|
| 本地后台 | 独立进程，保存授权和数据，运行同步、规则、统一任务队列及已有业务服务；不依赖浏览器、插件或任何页面存活 |
| 本地网页 | 在指定 Chrome profile 中打开本机地址：工作用 profile1，AI 测试用 profile10；提供现有写作、内容管理、分类模板、粉丝、规则和活动记录界面，只在使用时打开 |
| 启动与管理入口 | 日常启动、打开界面、暂停自动化、停止后台；无需终端或开发工具。快捷方式／小型原生托盘的具体形式由实现选择 |
| 浏览器插件 | 可选的 Tumblr 网页辅助和上下文入口；不是打开本地界面、保存数据或运行核心后台任务的前置条件 |

这次交付使用普通浏览器访问本地服务，不交付云端托管网站，也不要求安装 PWA。后台不能通过常驻 Electron、WebView、隐藏／无头浏览器或保持一个标签页来满足独立运行要求。进程是否带可见窗口不是判定依据。

本地网页承载工具自己的编辑器和管理界面。需要官网时按功能流程稿衔接准确目标并保存返回上下文；仅打开官网不算完成回复。额外内嵌官网窗口不是既定交付物，只有具体能力验证说明必要时再提出，不把技术外壳选择交回用户，也不改变独立后台与 profile 隔离要求。

## 2. 日常使用与生命周期

1. **打开工具。** 用户点工作入口。已有工作后台则复用；尚未运行则启动并等待就绪，再指定 Chrome profile1 打开本地界面。AI 测试使用单独入口，连接隔离测试后台并指定 profile10。地址、可用端口和就绪检查由工具处理；同一环境不能重复点击就启动多个后台或多个调度器。首版以 Windows 为交付环境；启动时明确选择 profile，网页业务本身不依赖插件或 Chrome 专属页面接口。
2. **编辑与管理。** 所有页面连接同一个后台，看到同一份数据库和任务状态。编辑期间显示真实的保存状态；只有后台已持久保存的草稿、附件或任务才可称为“已保存／已提交”。
3. **关闭网页／完全退出浏览器。** 不退出后台，不取消已接收任务，不要求浏览器后台模式，也不自动重开页面。自动规则和授权刷新继续；再次打开恢复已保存草稿、浏览上下文及任务结果。
4. **暂停自动化。** 暂停自动任务的新建及已排队自动任务的后续执行，保留队列、数据、记录及手动操作入口；已经执行中的请求完成必要的记录／核对，不伪装撤销已发出的请求。恢复后按当前规则重新核对队列再继续。
5. **停止后台。** 提供独立于关闭网页的明确操作，浏览器关闭时也能执行。停止前保存队列与执行状态；结果不明的请求保留待核对状态。页面仍打开时说明连接已断开，不继续显示任务正常运行或把未送达内容显示成已保存。
6. **电脑睡眠、关机、断网。** 睡眠／关机时本地任务不能执行；恢复后按已有规则、授权和去重逻辑核对再继续。断网不影响本机界面的加载和本地草稿保存，远端任务等待恢复。Tumblr 已接收的队列／定时发布仍与本机任务区分。

开机自启沿用现有“用户可选、初始关闭”的默认提案；启用后只启动后台，不打开浏览器。后台退出后，普通网页不能被当作启动本地程序的保证手段；启动入口必须能重新启动服务。端口占用、启动失败或后台已停止要给出能执行的恢复步骤，不能显示空白页或悄悄连接到占用端口的其他服务。

### 2.1 工作与 AI 测试的 Chrome profile 隔离

| 使用环境 | 指定浏览器身份 | 对应后台 |
|---|---|---|
| 用户日常工作 | Chrome profile1 | 正式数据目录、正式授权及工作任务 |
| AI agent 测试 | Chrome profile10 | 独立测试数据目录、独立访问会话／配对、默认 fake Tumblr 与测试任务 |

`profile1`、`profile10` 是用户指定的身份。实现前核对实际 Chrome 用户数据根目录及 profile 目录／标识，持久保存对应关系；不要仅凭显示名称、头像或数字猜测目录，也不要把指定身份重新映射成新建 profile。测试后台可以和工作后台同时运行，但不能共享数据目录、授权文件或任务队列；各自在本环境保持单实例。

- **所有浏览器入口一致。** 本地界面、Tumblr 首次授权／重连、打开帖子／举报页、插件跳转等均沿用所属环境的 profile。不能使用未指定 profile 的系统默认 URL 打开方式，也不能选当前活动窗口、最近使用的 profile 或扫描到的第一个登录会话。OAuth 回调必须回到发起它的后台及授权请求，不能把 profile10 的结果写入正式授权。
- **绑定可核验。** 工作／测试入口明确标出用途，并校验对应后台实例与账户身份；测试页面显著标记“测试”。启动前核对目标 profile，浏览器自动化操作前核对实际窗口／会话身份。仅看到 `chrome.exe`、某个页面标题或传入了启动参数不算已经证明命中了正确 profile。目录不存在、身份不明或工具无法保证选定 profile 时，明确报错并停止该浏览器步骤，不退回另一个 profile。
- **后台也分开。** 测试使用独立数据目录、监听端口／服务实例、访问凭据、OAuth 回调关联和插件配对；不读取工作凭据，不复用工作任务，不因同机发现正式服务就自动连过去。默认 fake Tumblr；需要真实账号验证时，按既有授权明确账号、博客及动作范围，测试浏览器身份本身不是对真实写入的授权。
- **不能只信 profile 字符串。** 普通页面请求中自报的 profile 名称不能作为权限证明。由受控启动入口建立正确浏览器会话，后台验证会话／配对凭据绑定的服务实例及用途；正式与测试凭据不能互用。Chrome profile 与 Tumblr 账号分别识别，不能以同名账号或同一个扩展 ID 代替 profile 绑定。
- **relay 和插件保持隔离。** 正式后台只接受已绑定工作 profile1 的配对实例；测试后台只接受测试 profile10 的配对实例。按各 profile 中独立的配对凭据识别连接，不能仅按扩展 ID 认领任何在线浏览器。工作 profile1 未开时，正式后台使用官方 API 或按能力等待，不能借用在线的 profile10 登录态。
- **后台不为保活打开任何 profile。** 无界面时按各自保存的授权执行；需要用户重连则记录待处理状态。自启、定时任务、额度不足或 relay 断开均不能擅自启动另一个 profile。
- **AI 测试不动工作窗口。** AI 自动测试只在 profile10 的已确认会话中进行，不打开／接管／导航／关闭 profile1 的页面，不读写它的 Cookie 或清理其站点数据。不能用通杀 Chrome 进程的方式测试退出。测试入口不调用工作入口；工作入口可先做启动参数／身份映射的模拟校验，实际工作 profile 验证须与测试证据区分。

资源与“所有浏览器退出”验收也受此边界约束：不得为了测试关闭工作 profile 或其他用户窗口。用户自行退出所有浏览器后的观测，或独立受控环境的验证，可以记录为全退出证据；只关闭 profile10 而 profile1 仍在运行，不能标为全退出通过。暂不具备条件时如实记录该项未运行。

## 3. 授权和本地数据

- 核心 Tumblr 操作继续使用后台持有的 OAuth 授权。首次授权／需要重连时可以打开浏览器；授权完成后，令牌刷新和任务执行不依赖 Tumblr 网页登录、浏览器 Cookie 或插件连接。
- OAuth 凭据、AI 密钥继续使用操作系统保护的本地存储。去掉 Electron 后应适配这一能力，不能退化为明文配置；延续单个刷新执行者、旋转令牌原子落盘及失败恢复规则。后台不把这些密钥下发给页面或插件。
- 数据库、草稿、原始附件、分类模板、规则、例外、任务进度和备份保存在工具的数据目录。浏览器存储只能是缓存／界面偏好，不能成为业务数据唯一副本；清除浏览器数据不删除后台数据，也不等于撤销 Tumblr 授权。
- 本地页面与后台的访问会话、Tumblr 的 OAuth 授权、Tumblr 官网的 Cookie 是三个不同边界。重开指定 profile 或清除本地站点会话后，可能需要重新建立本地访问会话，但不应无故要求重新授权 Tumblr；工作与测试环境分别保存，不能跨环境恢复授权。
- 授权过期／撤销时，保存本地工作并暂停受影响远端任务，界面提供重新连接；没有界面时先记录状态，不能为了重连自行启动浏览器。
- 写作自动保存保留现有范围。页面突然退出时，未送达后台的输入不能宣称已保存；附件上传中断须可恢复或明确重新选择。后台已保存的完整图文和排布必须可恢复，不能依赖关闭页面时才尝试保存。

## 4. 页面与后台的连接

以下是实现约束；具体框架、端口和 HTTP／事件接口由 Claude 选择。优先复用已有 `src/service/`、数据库和业务接口，为普通浏览器替换 Electron IPC 等系统适配。

- 由后台提供本地页面、静态资源和业务接口，同源部署是建议默认值。应用外壳、编辑和本地保存所需资源不能依赖外网 CDN；远端图片缺少缓存时沿用明确的联网提示。
- 服务只绑定本机回环地址，不默认开放局域网或公网。验证预期 Host、页面 Origin 和本地访问会话；变更接口须防跨站请求伪造，不能让任意网站或仅猜到端口的请求读写私人内容。插件继续使用单独配对的受限通道，不因增加网页界面而开放任意来源。
- 浏览器只调用必要的、结构化的业务操作；不能获得任意文件读写、任意地址代理或命令执行能力。文件选择／上传、下载备份、导入、系统路径和重启等原 Electron 功能逐项适配。页面选择的文件不能直接当成可信本机路径。
- 本地内容及操作状态接口需要同等访问控制；发布到 Tumblr 的授权不能代替本地页面的访问控制。凭据不进入页面源码、常规 URL、日志或导出文件。来自 Tumblr 的内容继续按不可信内容展示。
- 后台持久接收任务后返回任务身份；页面刷新、关页、断线重连或重复点击只查询／恢复同一任务，不重新创建发布／转发。请求是否送达不明时先按稳定操作身份查询，不能把连接失败直接当成远端操作失败。
- 同一使用环境的多个标签页和插件共享一个后台、一个队列、一个授权刷新执行者；工作与测试环境按第 2.1 节隔离，不能借多客户端支持跨接。对同一草稿的旧修订写入要检测冲突，不能静默覆盖另一页面的新内容。事件流或轮询只同步状态，不能承担业务定时器或调度器。
- 仅关闭页面与暂停／停止后台必须区分。长任务由后台执行，页面连接不是任务的生命期；前端断开后正常释放它的订阅及临时资源。

已有浏览器 relay 可以作为用户已打开浏览器时的可选通道；断开后支持的核心操作仍走官方 API，并遵守现有限额、退避和未知结果核对规则。不得为了节省 API 额度偷偷维持浏览器，也不得在写入回执未知时换通道重发。举报等已记录的官网限定能力继续明确标示限制；本次迁移不能把它们宣称为已支持的无浏览器自动化。

## 5. 迁移与交付顺序

1. **盘点复用。** 保留现有编辑器、内容查询／筛选、业务服务、数据库、队列和规则；列出 Electron 依赖的凭据保护、图片处理、对话框、文件操作、启动和退出能力，逐项替换适配层。新增文档不是重写所有功能的指令。
2. **独立后台。** 从现有 Electron 启动流程抽出无界面的服务入口及启动管理方式，覆盖启动、暂停、退出和恢复；单实例保护以数据目录为边界，不能只依赖 HTTP 端口。UI 尚未打开时即可运行已启用的任务。
3. **浏览器界面。** 接通普通浏览器中的业务调用、状态订阅、图片／文件流程和本地访问控制；复用界面，修复迁移造成的行为差异。现有内容页改进和粉丝模块需求继续交付，不以换运行方式代替功能验收。
4. **数据切换。** 迁移前保留可恢复备份；保留数据库身份、草稿附件、任务身份及未知结果、原有规则开关和已授权范围。迁移本身不发布、改帖或启用原先关闭的规则。已有授权能安全复用则复用，不能复用时解释需重新授权，其他数据仍保留。
5. **避免双重运行。** 旧 Electron 版与新后台不能同时管理同一数据目录或执行同一套任务，交付时必须验证切换保护。恢复旧备份须使用兼容版本，并确保另一执行者已经停止；不得将新格式数据库交给不兼容的旧版本写入。
6. **打包验收。** 日常用户通过启动入口使用，不要求自行安装 Node、数据库或开发工具；开发运行命令与日常入口分开说明。安装／更新保留数据和用户选择的自启状态。具体后端语言和打包器不在本次锁定。

既有 API 探测、单元测试和业务证据仍可复用；旧 Electron 包、仅打开网页截图或原有测试通过，不算此次运行方式迁移完成。业务规则以主稿及各专门文档的最新修订为准。

## 6. 内存与资源验收

用户确认的是降低常驻负担，尚未指定 MB 上限；本稿不凭空承诺占用数字或节省比例。硬性要求是：**浏览器完全退出后，工具后台仍工作，且工具不再保有 Electron／网页渲染／隐藏浏览器进程。** 如有不含浏览器引擎的启动管理进程，须计入后台总占用。

Claude 在同一台 Windows 机器、同一份测试数据的独立副本和规则配置下顺序对比以下状态，注明构建版本、进程范围、采样时间和内存口径；建议每种空闲状态等待稳定后观察至少 10 分钟，后台任务执行峰值另外记录。浏览器操作仅限 profile10；工作 profile1 是否运行须如实记录，不能为了凑齐状态擅自退出它。

| 状态 | 需要记录 |
|---|---|
| 原 Electron 版关闭到托盘 | 旧方案的全部应用进程、内存及空闲 CPU，作为迁移前基线 |
| 新后台独立运行，浏览器完全退出 | 全部后台／启动管理进程的内存、空闲 CPU、任务执行情况；核实没有工具持有的浏览器进程 |
| 浏览器打开本地界面 | 后台与浏览器分别记录；声明测试浏览器、其他标签页及扩展条件，不能把浏览器占用排除后称为使用时总占用 |
| 多次打开并关闭界面后 | 后台是否残留订阅、上传临时资源或额外进程，内存是否持续增长，以及任务和数据是否正常 |

必须交付同口径对比和解释；如常驻占用未降低，应定位原因并继续优化，不能仅以去掉 Electron 名称或安装包变小宣布达标。内存口径建议分别报告进程组的私有工作集和私有提交量，不能拿不同口径相减。此处定义测量方法，不记录未经实测的成绩。

## 7. 验收场景

默认使用隔离测试后台、虚构数据和 fake Tumblr 验证任务、故障及重复提交；本机浏览器实测仅使用 profile10，遵守第 2.1 节。工作 profile1 的入口模拟校验、用户实际使用检查及测试环境实测分别记证据。文档更新不授权新的真实发帖、改帖、拉黑或举报；确需真实账号验证的动作按既有授权边界处理。

| ID | 场景与通过条件 |
