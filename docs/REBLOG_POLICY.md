# Reblog：正文快照、标签同步与新版本转发

确认日期：2026-11-06。本文件是桌面端、插件和素材收集共同遵守的 reblog 定义，优先于其他文档中旧的“同步副本”“修复差异”“原帖覆盖转发标签”规则。本次更新的是需求与定义，现有代码是否符合另见[实现状态](DESKTOP_IMPLEMENTATION_STATUS.md)。

**用户修订（2026-11-06，晚）：** 自己原帖的 reblog 快照，**标签始终与原帖同步**（内容、顺序都一致），正文、图片、排布和所属版本仍然冻结。标签修改仍不算原帖修改：不产生新版本，也不触发再次转发，只是把各条 reblog 的标签改成原帖当前的标签。别人的帖子和素材收集的 reblog 不在此列，创建后标签仍不改。下文与此冲突的“固定标签”说法以本条为准。

## 1. 固定的是转发时的正文（标签跟随原帖）

- 一次 reblog 是一份独立的历史快照：保留创建时取得的正文、图片、排布和说明。自己原帖的 reblog，标签跟随原帖当前的标签（含顺序）。
- 转发创建后，软件不再编辑这份快照的正文；原帖正文更新、AI 重整和管理归属变更都不能改写它。原帖的标签改了（在 App 里或直接在 Tumblr 上），各条 reblog（各个博客、各个版本）的标签随之改成一样，只改标签、整帖读回核对。
- 原帖正文、图片或排布变化时，再创建一条 reblog 保存新版本。**只改标签不算新版本，不触发再次转发。** 旧 reblog 保留原来的 ID、链接和正文，标签与原帖保持一致；不删除重建旧版。
- “修改原帖”是修改真正的源帖，不能通过修改一个旧 reblog 来代替。自己无权编辑的原帖，只能读取已可访问的新版本，不能改写原作者内容。
- 适用于自己的跨博客转发、别人的内容及素材收集。素材标签和 AI 说明可在首次创建前确定；创建后不能继续写进已有 reblog。后续分析可保存在本地，任何新转发仍须经过明确的手动操作或已启用规则。

例如：原帖内容为 A、标签为 `art, sketch`，转发得到 R1。仅把标签改为 `art, finished` 时，不创建 R2，R1 的标签改成 `art, finished`、正文仍是 A。之后原帖内容改成 B，下一次符合规则的分发创建 R2（内容 B）；R1 和 R2 的标签都跟随原帖。

## 2. 展示管理与内容版本分别处理

本规则固定正文与内容版本，自己的转发标签按专用规则同步。公开／隐藏、长期公开、期限和明确删除仍各自执行；不会改写快照正文或制造内容版本。

若可见性接口要求完整帖子载荷，必须读回并原样保留该 reblog 自己的正文、排布和标签，不能取最新原帖来拼装；不能保证保留时暂停该操作。社区标签等能力门槛继续适用。原帖可见性变化不自动复制到转发，只有明确选择的实例操作或展示规则能改变转发的状态。

详情按“逻辑作品 → 源版本 → 实际转发实例”展示；同一目标博客可以保留同一作品的多个历史版本。管理归属仍只认真实关系和既有规则，多次转发到同一子博客不算多个管理者。批量改正文时排除已有 reblog；批量改标签只改原帖，reblog 随后跟随原帖的标签；公开／隐藏的预览仍可选择具体实例。

### 2.1 在应用里集中维护各版本

用户确认各次 reblog 要方便维护，不能只有底层版本记录。入口放在应用的作品详情“版本与转发”，内容卡片提示版本数和待处理数量；从任一原帖或转发进入都定位到同一作品及选中实例。插件仅负责打开这个入口，不再做另一套版本管理。

- **一处看全。** 版本按已观察到的修订顺序排列，可展开各目标博客的转发。分别显示源版本首次观察时间、实际转发时间、博客、原链接、缩略图／摘要、当前公开／私密／队列状态、长期公开等例外，以及分发成功、待处理、失败、结果未知或已删除状态。时间含义不能混淆；“最新已知源版本”和“该博客最新已核实转发”分开标示，不能把待发送版当成已上线。
- **看清差异。** 比较正文修改、图片增删／替换／顺序和排布；创建时提交标签保留为历史，当前已观察标签另行展示，标签差异不计入内容版本。快照或媒体不足时标明无法比较，不能仅凭图片数判定相同。历史版本未知时明确标记，不根据时间或相似文本硬猜。
- **缩小范围。** 可按博客、版本、实际状态、长期公开例外和任务状态筛选；支持选择单个实例、一版的全部自有转发，或明确范围内的多个版本。分页／未同步历史必须标明覆盖，不能把“当前页全选”冒充“所有版本”。
- **常用维护。** 在同一处执行公开、隐藏、长期公开、回到展示规则、打开原链接和删除选定转发。删除独立于隐藏，确认中列明永久删除的博客、版本及帖子；默认不选实际原帖。所有写入复用应用队列，一次预览列出目标、排除项、例外及管理关系影响，结果逐条核对。没有权限／不能保留快照载荷的实例列出原因并跳过。
- **快捷整理旧版。** 提供一次性的“保留最新公开版，隐藏旧公开版”预览：逐个所选目标博客保留其最新已核实且当前公开的转发，旧公开版本列为候选；长期公开例外、未知版本和未核实结果不自动纳入。最新源版本尚未成功公开时不把旧版先藏掉；没有可核实公开版时不自动操作。此操作不发布私密新版、不删除旧版、不触碰实际原帖，也不会变成“以后每次发新版都自动隐藏旧版”的新规则。
- **处理分发问题。** 显示哪些博客已有哪一版、哪里缺少当前内容版、被排除、失败或结果未知。重试之前仍执行原有版本去重与结果核对；不能用“补发”绕过未知结果、删除记录、私密来源或排除规则。只在能够取得并核实指定内容版本时提供相应转发动作，不能承诺任意旧版都可再次从原帖取得。
- **记住个人整理。** 可给版本添加仅本地的简称或备注，随备份保留，不写成 Tumblr 标签、不改变源内容版本。删除某个转发后保留版本关联和删除记录；下次同步不会把它重建。若删除会使管理关系需要复核，预览先说明，不能自动换管理博客。

新版本出现不会自动清理旧版本。用户主动整理版本属于明确的实例管理；既有按年龄隐藏规则仍按其已选范围和例外执行。任何部分失败都保持真实的逐实例状态，不能声称整个版本已隐藏或删除。

## 3. 更新发现、路线和去重

1. **版本来源。** 保存源帖稳定身份、观测到的版本 ID、正文／媒体／排布指纹，并另外保存每次转发的有序标签快照。内容版本指纹不包含标签、阅读量、notes、抓取时间、可见性、管理归属和非内容性的传输字段。标签增删、拼写或顺序变化都不产生新版本，也不触发再次转发。
2. **变更发现。** 同步必须检查已转发源帖的更新，不能只看首次发布时间晚于启用时间的新帖。只处理实际观察到的版本，不声称还原两次扫描间所有编辑历史。迁移先建立基线，不把全部旧帖当成刚修改过；历史补发仍需预览。
3. **再次转发。** 已启用路线对符合条件的新源版本安排一次新转发；未启用时展示“原帖已更新，可再次转发”，由用户操作。它不会自动扩大目标博客范围、开启路线、公开私密原帖或循环转发自己的历史快照。目标博客本来持有实际原帖时，仍不往原帖所在博客回转。
4. **版本去重。** 以“源帖身份 + 源版本 ID + 目标博客”持久去重，记录目标帖子 ID、提交标签和内容指纹。相同版本重扫、重启、重试或修改路线设置都不重复创建；存在旧版 reblog 不能阻挡新版。版本 ID 表示观察到的修订，而非只用内容哈希：已观察到的 A → B → A 是三个修订，不是永远禁止再次分发 A。
5. **删除记录。** 用户删掉某一版本的转发后，该版本留下删除记录，不自动重建；之后的真实新源版本仍可按已启用路线转发。停止所有后续版本使用停用路线／排除源帖等明确操作，不能从删除一个旧版推定。
6. **标签与排除规则。** 每个内容新版本按该次真正要转发的源帖当前完整标签判断。含排除标签就跳过整次转发，不把标签删掉后转发。标签改变可使尚未发送的计划重新检查资格和提交标签，但不能制造新版本或触发已完成版本再转发；移除排除标签也不自动补发已跳过项。新增／移除排除规则不改写旧快照，历史补发须单独预览。
7. **取源与并发。** 新版必须从能提供更新内容的真实源帖转发，不能把旧 reblog 当成最新版本。发送前重读源帖并验证版本，已变化则重做未发送计划；发送后验证实际取得的内容和标签。平台无法取得指定版本或实际结果不符时，显示未核实／冲突，不靠编辑刚创建的 reblog 来“修正”，也不自动再发一条掩盖问题。
8. **未知结果。** 回执丢失先查找并核对该次版本和目标，不能只凭相同根帖认领任意旧版，也不能凭有限搜索没找到就重发。原任务结果未明时，暂停同一路线源帖的后续版本创建，避免乱序和重复；原稿和待分发版本保留。

## 4. 旧规则的迁移

- 停止并作废冲突的旧正文覆盖／通用副本修复任务；保留符合当前规则的自有原帖标签同步意图及开关，不因迁移启用或执行。已发送且结果未知的操作先核对，不假装取消就撤回了远端变更。
- 保留现有 reblog 的实际内容，不以当前原帖修复差异；无法确定它来自哪个历史版本时记为“版本未知”，不能虚构历史。
- 数据读取仍可叫“同步”；reblog 功能改称“转发／转发新版本”，差异显示“历史版本／源帖已更新”，不再叫“漂移／修复副本”。
- 旧版插件的 `syncCopies`、`copyFrom`、差异修复及素材 AI 回写等行为，与此定义冲突的部分必须调整。原有测试通过不代表新规则通过。

## 5. 验收

| ID | 场景与预期 |
|---|---|
| R01 | 原帖正文变化：新增 R2，R1 正文、图片、排布及链接不变（标签跟随原帖） |
| R02 | 仅标签变化，包括增删和顺序：不产生新版本、不再次转发；R1 等所有自己原帖的 reblog 只把标签改成原帖的标签，正文不动 |
| R03 | 同一版本重扫、重启、超时恢复：最多一个已核实的目标实例；未知结果先核对 |
| R04 | 目标已有旧版：新版仍能创建；旧版不能被误认成新版的回执 |
| R05 | 删除 R1：同一版本不重建；源帖的新版本仍按路线分发 |
| R06 | notes、可见性、管理归属或扫描时间改变：不产生内容新版本；明确隐藏操作保留快照正文和标签 |
| R07 | 新版本命中排除标签：不转发且旧版不变；关闭路线不自动发新版 |
| R08 | 同一子博客有多个版本：管理者仍唯一；详情显示每个版本，标签批量操作只改原帖，快照随后跟随 |
| R09 | 素材 reblog 创建后的手动整理、模板和 AI 操作不修改其正文或标签 |
| R10 | 迁移不重写历史正文、不执行额外远端写入、不批量重发，保留允许的标签同步规则及任务；已观察 A → B → A 可分发三次，重复观察不重复分发 |
| R11 | 源帖在发送前后发生变化或源帖已私密：明确延期／冲突，不取旧快照伪装新版，不临时公开原帖 |
| R12 | 从作品、原帖或任一转发进入同一版本详情；跨博客多版本一处可见，源观察时间／转发时间和源最新版／已核实转发版分别显示 |
| R13 | 比较两版显示正文、图片与排布变化，标签差异单列且不产生版本；缓存不足／版本未知如实显示，不能推断内容相同 |
| R14 | 按博客／版本／状态筛选并批量维护，预览列明实际帖子、例外和覆盖范围；部分失败逐条保留，未选版本和原帖不受影响 |
| R15 | “保留最新公开版，隐藏旧公开版”逐博客计算，尊重长期公开；最新源版待发／私密／失败／未知时保留现有公开版，且无新版到来时的自动清理 |
| R16 | 明确确认后删除选定历史转发，保留版本删除记录与本地备注；原帖不被连带删除，管理关系变化先预览，再同步不会重建 |
| R17 | 补发／重试仍遵守版本去重、排除、能力和未知结果规则；本地简称／备注经重启和备份恢复保留，但不改远端正文、标签或版本号 |

这些是实现待满足的规则；本次文档修订不执行转发、改帖、删除或开启自动化。
