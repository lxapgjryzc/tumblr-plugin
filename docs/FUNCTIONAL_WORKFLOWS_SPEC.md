# 功能流程与整体验收

更新：2026-11-07。状态：需求交接，代码由 Claude 实现。本文件不宣称任何新增能力已实现或验收。

## 1. 本轮确认与设计责任

- 用户确认：看到互动应能顺手回复，看到自己的帖子应能编辑，日常操作尽量在工具内连贯完成，避免在两个地方重新找人、找帖和登记结果。
- 用户不在意统一自制界面、官网接入或混合实现之间的技术选择。实现者依据能力、体验和资源负担决定，不要求用户先选技术外壳。
- 用户不想讨论首页优先展示内容还是待办、具体发布交互、自动化设置方式。此前对此的猜测不构成确认，也不据此增加必选配置或改变规则。实现者提出可检查的具体设计并标明设计选择。
- 已确认的低常驻负担、独立后台、profile1 工作／profile10 测试隔离继续有效。默认沿用本地网页；只有具体功能缺口的验证说明有必要时，才提出额外界面适配，不能为了保存登录态常驻一个浏览器引擎。
- 本轮不增加完整私信产品、关注流、公共主题、素材库扩展或营销自动回复。没有公开接口的能力须记录验证缺口，不能推定不可能，也不能承诺已支持。

本文件定义跨模块的功能流程和产品完成标准；运行与隔离以 [LOCAL_WEB_APP_SPEC.md](LOCAL_WEB_APP_SPEC.md) 为准，内容查询以 [CONTENT_BROWSER_UX_SPEC.md](CONTENT_BROWSER_UX_SPEC.md) 为准，版本及标签以 [REBLOG_POLICY.md](REBLOG_POLICY.md) 为准，粉丝与保护分别遵守其专门文档。它覆盖粉丝稿中把“打开官网、回来手工标记”当作完整交付的旧安排，不取消真实结果与用户自报的区别。

## 2. 从功能决定运行职责

| 功能 | 运行职责与体验要求 |
|---|---|
| 图文创作与已发布原帖编辑 | 操作界面提供编辑、预览和保存；后台保存完整文档／附件、执行和核对发布或修改 |
| 浏览、筛选、分类、批量操作与版本维护 | 界面保持查询和位置；后台提供权威数据、精确目标及任务结果 |
| 到期隐藏、版本转发、自己的转发标签同步、已启用的素材收集 | 后台按当前规则独立执行；关闭页面不停止，规则范围和手动例外不因迁移改变 |
| 粉丝关系、互动与保护 | 后台同步和记录；界面展示前情并承接处理，保护能力继续单独验收 |
| 平台相关交互，例如回复 | 优先经已验证接口直接处理；必要时接入正确身份的官网操作，保留原互动上下文和恢复入口 |
| 插件 | 页面辅助、上下文与受限适配；业务身份、数据、任务和执行结果仍归后台，不另起调度或完整管理系统 |

按需官网能力与无浏览器后台能力分别标示。未验证的回复、私信或举报不能被“核心功能都能走 API”笼统覆盖。反过来，官网动作需要页面，也不能使已有后台同步、隐藏与转发依赖页面存活。

## 3. 写作、发布和修改形成完整流程

### 3.1 新建图文

从内容区或写作入口进入 → 编写文字和加入图片 → 使用按钮／键盘完成支持的排布 → 按需选择可选分类和模板 → 检查真实标签顺序、博客、状态及既有路线影响 → 提交 → 在同一作品中查看核实结果。

草稿保存、发布提交和远端成功是不同状态。关闭页面前后台已确认的文档和附件可恢复；发布回执未知时保留原任务核对，不重复创建。具体默认选项由设计者提出，不能把未确认的“全自动发布习惯”写入产品规则。

### 3.2 编辑已发布内容

1. 从作品或实际帖子详情发起编辑，展示实际可写原帖及所在博客；从历史转发进入时明确转到原帖编辑，保留所选历史实例的返回入口。
2. 取得原帖当前正文、图片、排布和必要字段，保存编辑基线。不能仅凭本地原草稿覆盖官网／手机端后续修改。
3. 使用同一编辑器修改支持的内容；不支持的块保留或明确限制相关编辑，不能静默丢失，也不能把未实现写成平台不支持。
4. 提交前重新核对远端基线；冲突保留两份内容并让用户选择处理，不能静默覆盖。提交的是同一个原帖的修改，保留 ID／链接，不以另发一篇代替编辑。
5. 后台核实实际结果，并按既有版本规则记录内容变更。仅已启用路线处理新的内容版本，标签修改不造新版本。已存在的转发正文不变；自己的转发标签按既有规则同步。
6. 返回原列表的筛选、位置及作品详情；显示原帖更新与各路线后续结果，不把原帖改成功当成全部分发成功。

“已发布草稿只读、去官网修改”可以记录为过渡能力，不能作为此流程完成的证明。

## 4. 发现互动、处理和恢复上下文

### 4.1 用户流程

从一条互动进入 → 查看实际帖子、讨论和人物前情 → 发起回复 → 确认发送身份、目标与内容 → 提交或进入已定位的必要官网操作 → 得到真实结果／明确待核实状态 → 留在原互动或返回原列表。

保留筛选、滚动位置、目标身份、所选讨论与未发送文本；转去官网时不丢失这些上下文，不要求用户从官网首页重新寻找。若受平台限制无法定位具体回复位置，说明限制并提供最接近的准确入口，该缺口保持可见。

### 4.2 适配顺序与能力验证

- 先列出动作级能力：读取通知、读取讨论、发送普通回复、读取／发送私信、Ask、举报分别记录，不能互相代替。区分文档支持、实现、模拟测试、真实验证与限制。
- 优先使用已验证官方接口；对未建立公开接口能力的普通回复，评估受限网页适配或官网流程衔接，先做能决定可行性的最小验证，再确定实现。不存在可用证据时保持“待验证”，不以端点猜测承诺功能。
- 默认本地网页可继续作为主界面；是否需要额外窗口由具体接入证据决定。官网打开／授权／插件连接必须沿用所属环境的 profile，身份不明停止，不能借另一个 profile 的登录态。
- 没有可验证通道时允许准确的官网入口与本地记录作为过渡，但明确“集成回复未完成／受阻”，不能把过渡流程算为完整功能交付。完整私信收件箱仍不因本轮被承诺。
- 模拟验证覆盖目标选择、状态和恢复；真实测试遵守既有授权，不因修改需求新增向真实用户发送测试消息、回复或举报的授权。

### 4.3 写入和完成状态

- 工具发起的发送由后台先保存操作身份、账号、博客／发言身份、目标讨论与提交文本，再交给受限适配器执行。插件不得接受任意 URL、脚本或代理请求，不保存另一套待发送队列。
- 用户在官方页面直接手工操作时，记录为官网操作交接；不能声称已纳入工具发送队列。仅在取得足够回执或可核对结果时升级为“发送已确认”。
- 区分打开页面、已读、本地已处理、用户自报已回复、发送待核实和发送已确认。自动观测与人工声明分别记录；关闭窗口或点击“已处理”都不证明发送成功。
- 工具发送回执丢失时保持未知并核对；刷新、双击、关闭页面、切换适配器或重新打开不能盲目重发。平台证据不足以确定结果时保留待处理，并提供人工核对入口。
- 本轮只要求用户主动发起的回复；不默认启用欢迎语、自动回复或 AI 自动发送。AI 草稿与真正提交是两步。
- 需要网页的动作在浏览器退出后显示等待条件；不为此重新打开浏览器。其他无浏览器任务继续运行。

## 5. 三类验收分别记录

| 类型 | 通过意味着什么 | 不能代替什么 |
|---|---|---|
| 运行迁移 | 独立后台、按需界面、身份隔离、持久保存与资源测量满足 LW 场景 | 不能证明编辑器或互动处理可用 |
| 功能行为 | 编辑、筛选、版本、标签、隐藏、粉丝等满足各自业务规则 | 不能只凭接口成功或测试总数证明日常体验 |
| 完整使用流程 | 在明确场景中走完操作、故障恢复和上下文返回，有可复现证据 | 不能以截图、占位按钮、打开官网或手动标记代替实际完成 |

现有 A／LW／CU／R／FR／F 场景继续适用；被后续规则修订的场景重新验收，不沿用矛盾的旧通过记录。状态表逐项记录版本、数据、结果、证据、限制和剩余工作。受阻功能可交付过渡版，但整体验收不得因此标为全部完成。

## 6. 跨模块验收

| ID | 场景与通过条件 |
|---|---|
| FW01 | 新建图文，非拖拽排图，选择可选分类／模板，保存、预览、发布并回到作品；实际图文与标签顺序正确，后台确认保存后重开仍完整 |
| FW02 | 从跨博客作品及历史转发分别进入已发布原帖编辑；显示正确目标，修改保留原帖 ID／链接，历史转发正文不变，返回原查询位置 |
| FW03 | 编辑期间有官网改动／不支持的内容块／断网；保留文档和附件，冲突或限制明确，未核实写入不显示完成，不覆盖新内容 |
| FW04 | 原帖正文修改与仅标签修改分别执行；前者仅沿已启用路线产生新内容版分发，后者仅按既有规则同步自有转发标签，均不改写旧版正文或擅改可见性 |
| FW05 | 从互动进入帖子和人物前情后发起普通回复；身份与目标正确，发送文本及结果可追溯，返回原互动位置；仅打开官网／手工标记不能通过集成发送项 |
| FW06 | 工具回复双击、回执丢失、刷新、断线和重新连接；恢复同一操作且不盲目重发，未知结果与已确认发送分别显示 |
| FW07 | 官网交接保留目标、上下文和未发送文本；正确 profile，官网手工操作不伪称工具队列执行，用户自报与可核对发送结果分开 |
| FW08 | 浏览器退出时，网页限定动作等待且不自行打开页面；已启用核心后台任务继续。插件缺失只影响确实依赖它的动作 |
| FW09 | 同一作品的原帖编辑、标签同步、版本分发与可见性操作交错；各任务针对正确实例和修订，分别核实，部分成功不冒充全组完成 |
| FW10 | 基础通知／人物／待办／保护共用真实身份与覆盖信息；回复失败或未知不自动标为发送成功，新互动不继承旧处理结论 |
| FW11 | 迁移与备份恢复保留草稿、附件、关系备注、互动处理和未知发送记录；不重新发送或扩大原规则范围 |
| FW12 | 交付表分别列运行、功能、完整流程证据；未验证回复通道、正文编辑缺口及资源未测均不能被“网页版已启动”掩盖 |

实现顺序按依赖安排：先统一规则与动作级能力表；在迁移后台和界面的同时核实回复通道、补齐原帖编辑；再联调上述流程。不要等整个外壳迁完才发现最主要的交互缺少可用通道。
